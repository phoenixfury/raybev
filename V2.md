# RayBEV-Lite v2: OpenCV fisheye, 96 m BEV, TDA4VH-oriented inference

**Current task-head/training contract: [TASK_V3.md](TASK_V3.md).** The geometry
here remains current; the old global-yaw/absolute-size/three-output and sampler
descriptions below are historical. New defaults add binned heading, training-only
class-relative dimensions and class-balanced supervision. Old checkpoints keep
their old semantics through `ModelConfig.from_checkpoint`.

The defaults in `raybev/config.py` now describe architecture version 2. Old
1.13M-parameter checkpoints cannot resume this architecture. Start a fresh
training run; original checkpoints and metrics are retained in their old paths.

Calibration/frame correction: the four-bag DetZero labels are **CLIDAR**, not
BASELINK. Even the previous v2 server checkpoints need a **fresh run** after
this correction. Do not pass `--resume` or initialize from their detector
weights; use the default ImageNet backbone initialization and a new output
directory. Resume is appropriate only for an interrupted corrected run with
the same recipe, camera/LiDAR calibration hashes, and world size.

## Architecture

| Item | v1 | v2 default |
|---|---|---|
| BEV extent | ±30 m | ±48 m, X and Y |
| Output cell spacing | 0.30 m | 0.25 m |
| Output grid | 200×200 | 384×384 |
| Camera image size | 800×640 | 800×640, native aspect preserved |
| Image backbone | MobileNetV2-0.75, random | MobileNetV2-1.0, ImageNet V2 in trainers |
| Image pyramid | summed /8,/16,/32 | geometry-conditioned /8,/16,/32 gates |
| Transport features | 48 channels × 3 concatenated planes | 32 channels pooled across 4 planes |
| Heights, BASELINK meters | 0.4, 1.2, 2.0 | 0.4, 1.4, 2.4, 3.4 |
| BEV context | three full-grid separable blocks | residual /2,/4,/8 encoder + nearest-upsample neck |
| Detection | shared 8-channel regression branch | independent offset, Z, size, yaw + quality branches |

Finer BEV spacing improves center sampling; the multiscale context and upper
height planes address the extent and height of trucks/buses. Camera resolution
stays 800×640 to contain image compute. Increasing BEV spacing precision does
not manufacture detail in distant image objects.

The adaptations from ROSA are calibrated ray feature lifting, observation
quality cues, learned feature-level/view/height weighting, wider spatial
context, task-specific heads, and quality-aware detection ranking. No query
transformer, deformable CUDA operation, dense depth volume, or velocity head
is added. The camera weighting is feature/geometry dependent and each height
has its own image confidence channel. Heights are pooled before the BEV CNN;
this deliberately trades separate vertical features for a smaller memory bus.

These are lightweight **attention-like gates**, not Q/K/V multi-head or
transformer self-attention: per-pixel sigmoid gates select pyramid levels,
and learned per-height confidence weights camera observations during transport.
They are already part of v2; the calibration correction adds no new attention.

## Calibration contract

The supplied JSON uses **OpenCV fisheye/equidistant** intrinsics and four
distortion coefficients. Both projection and inverse ray cues use those exact
values. No OCam lens conversion is applied. `T_BASELINK_CAMERA` maps camera
coordinates into BASELINK. RGB camera order is ARC_F, ARC_R, ARC_SL, ARC_SR.
Image resizing and LUT coordinates use the same half-pixel convention.

Eight per-camera image cues encode unit ray XYZ, normalized UV, incidence
angle, image border margin, and radial distortion derivative. They are
computed once at stride 8 and are an explicit encoder input during deployment.
The static reliability prior also incorporates lens angle and image margin.
The configured 105-degree half FOV is preserved; change it only to a measured
lens value. Positive-Z OpenCV projection is tested against `cv2.fisheye`.

Some ROSA PKLs contain serialized OCam metadata. RayBEV reads these as passive
metadata for compatibility and uses only the JSON calibration for projection.
Use native aspect-preserved camera images, not OCam-remapped 800×800 views.
Matching the image pixels and sensor extrinsics still matters across bags.

The active camera transforms now match the four converted bags' source
`calibration.json` records and their ROSA `lidar2cam` matrices. The old
RayBEV-only manual camera adjustments are removed; OpenCV K/D are unchanged.
Both active calibration JSONs contain the same cameras and `T_BASELINK_CLIDAR`.
The rounded/recovered CLIDAR transform is inherited from the source metadata,
not newly measured physical calibration; inspect overlays for any new rig.

All three trainers and `RosaCombinedDataset` default to `--box-frame CLIDAR`.
Raw files remain untouched. Centers and heading vectors are transformed once
into BASELINK **before** range filtering, targets, sampling and evaluation.
The grid, height planes and decoded boxes remain BASELINK. Use
`--box-frame BASELINK` only for labels already converted. `--lidar-calibration`
defaults to the same file as `--calibration`, avoiding two independent rig
defaults. Bottom-Z inputs are centered in their source frame before rotation.

For historical server-checkpoint inference/comparison, explicitly select
`--calibration configs/legacy_v2/calibration_baselink.json`; that archive has
the original checkpoint SHA256. It is not for new training. Existing video,
metrics and weights are preserved and still describe the old geometry.

Validation of this correction: 42 focused tests passed; all 3,787 train and
674 validation frames loaded with CLIDAR defaults. Across all four bags,
19,167 visible validation-center projections agreed with the source rig to
within 0.00008 native pixels (numerical consistency, not physical calibration
accuracy). A downscaled real-frame forward/backward passed with local ImageNet
weights and finite gradients. The old server `last.pt` was rejected for resume.
No corrected full training run or TDA4VH board benchmark has been performed.

## Targets, losses, and decode

Box order remains `(x,y,z,l,w,h,yaw,class_id)` with center Z and radians.
Both combined trainers filter GT centers to `[−48,48)` in X/Y before counting,
sampling, target creation and validation. Decoding uses the same bounds.

Targets use the CenterNet minimum-overlap Gaussian radius (overlap 0.1), based
on the full vehicle footprint. CPU vectorized patch drawing avoids thousands
of GPU scalar synchronizations. Positive focal weights in class order
`car,pedestrian,cyclist,truck,van,bus` are now `(1,2,4,4,4,4)`.
Per-object box regression and quality supervision use the same difficulty
weights. Offset, Z, size, yaw and yaw-norm errors are all included. The loss
divides by the unweighted center count, so a difficult object's weight does
not cancel out in a single-object microbatch. Dense heatmap background
penalties are unchanged, and empty/background frames remain supervised.
These bounded manual weights are initial settings, not data-fitted optima or
full inverse-frequency balancing. No class-dependent score boost is applied.
The heatmap starts with a 1% foreground prior to control the much larger
grid's initial dense-negative loss.

Regression uses separate channel weights `(2,2,1,1,1,1,1,1)`, normalized
sin/cos yaw and a unit-circle penalty. The cosine bias starts at one, avoiding
an undefined zero-vector yaw. A quality head learns detached center/relative
size accuracy at GT centers. For new runs, confidence is
`sigmoid(class_logits) * sqrt(sigmoid(quality_logits))`. This softens the old
product's quality penalty while keeping confidence at or below the class
score. Local 3×3 peaks are selected **after fusion**, so a neighboring
better-quality detection is not removed solely by a larger raw class logit.
Non-finite class, quality or regression predictions are masked before top-k;
fusion and box decoding run in FP32 even with AMP outputs. Class-aware rotated
BEV polygon NMS stays at IoU 0.25. Scores are ranking confidences, **not calibrated
probabilities**; thresholds and false positives must be evaluated after retraining.

`quality_score_power=0.5` and `score_peak_mode='fused'` store this rule in the
checkpoint config. Old v2 checkpoints without these fields retain exponent 1,
heatmap-first peaks and unweighted regression when loaded with
`ModelConfig.from_checkpoint`. Resume rejects a changed config/loss recipe.
The comparison tool shares the decoder's score function, and export metadata
records the exponent and peak order for the Arm/C7x postprocessor. This change
adds no network parameters, output channels or learned-graph operators.

The forward contract is now three tensors:

```python
heatmap_logits, regression, quality_logits = model(images)
# [B,6,384,384], [B,8,384,384], [B,1,384,384]
```

`make_targets` still returns heatmap, regression, mask by default. All trainers
pass `return_class_ids=True` to append an exact regression-owner class map;
this handles overlapping class centers without assigning a Bus box the Car
weight via heatmap argmax. Three-target loss callers are supported for
unambiguous centers; ambiguous weighted centers require the owner map.
Pass `cfg=cfg` into `detection_loss`. `decode_detections` still returns `[N,9]`
per frame. Portable rotated NMS stays outside the TIDL graphs.

Loss/scoring validation: 67 focused tests passed, including exact per-class
gradient ratios, unchanged background penalties, collision ownership, empty
GT backward, FP16-input/FP32-score handling, fused-peak ordering, non-finite
candidate rejection, legacy scoring and ONNX subgraph parity. A two-process
CPU DDP test passed with Truck/Bus supervision and alternating empty ranks;
a real bus-containing frame passed pretrained-backbone forward/backward with
finite gradients. A smoke export verified the new host scoring metadata.
These are correctness checks, not measured retrained accuracy or TDA4VH speed.

## Train a fresh model

From `projects/raybev_lite`:

```bash
python scripts/train_combined_rosa.py \
  --root /home/mostafa/mmdetection3d/data/Custom/raybev_4bags_native_800x640_v2 \
  --box-frame CLIDAR --z-reference center \
  --epochs 24 --batch-size 1 --workers 2 --amp \
  --out work_dirs/raybev_v2_48m_clidar
```

ImageNet MobileNetV2-1.0 weights are loaded by default. TorchVision downloads
the official `mobilenet_v2-7ebf99e0.pth` on first use; a download/load failure
raises an error. For offline training, provide the downloaded official file:

```bash
--backbone-weights /path/to/mobilenet_v2-7ebf99e0.pth
```

Use `--no-pretrained` only for an explicit random-init ablation. Constructing
`RayBEVLite` directly defaults to no download so inference/tests/export remain
offline; request `pretrained=True` when initializing a new model in your code.

Both combined trainers now use bounded class-presence repeats (max 3 per
original frame, empty frames retained), mild photometric augmentation, AdamW
weight decay 0.001 excluding biases/normalization, backbone LR multiplier 0.5,
500 optimizer-step linear warmup and cosine decay. Controls are
`--no-balance`, `--no-augmentation`, `--backbone-lr-mult`, `--warmup-steps`.
The NPZ trainer shares pretraining/optimization/losses but does not use
class-balanced sampling or the combined-dataset augmentation.

Two GPUs, effective batch eight:

```bash
torchrun --standalone --nproc_per_node=2 scripts/train_combined_rosa_ddp.py \
  --root /path/to/raybev_4bags_native_800x640_v2 --box-frame CLIDAR \
  --epochs 24 --batch-size 1 --accum-steps 4 --workers 2 --amp \
  --out work_dirs/raybev_v2_48m_clidar_2x3080ti
```

Or use `bash scripts/launch_2x3080ti.sh`. Profile memory before increasing the
microbatch. DDP validation remains exact, without duplicated padded frames.
Resume only v2 runs with the same recipe, world size, calibration, and data.
Checkpoints carry architecture config, input label frame, initialization
source, recipe, camera and LiDAR calibration SHA256, optimizer, step scheduler,
and scaler state. Incompatible resumes are rejected.

The current lightweight evaluator remains a diagnostic evaluator. It is not
equivalent to ROSA's released metric; improved scores must be evaluated under
the same class set, range, and official metric before claiming ROSA parity.

## Export and target integration

```bash
python scripts/export_onnx.py --checkpoint work_dirs/raybev_v2_48m_clidar/best_map.pt \
  --calibration configs/calibration_baselink.json --output exported_v2
python scripts/profile_model.py --calibration configs/calibration_baselink.json \
  --output model_profile_v2.json
```

Exports are fixed-shape ONNX opset 17:

- `image_encoder.onnx`: RGB `[1,3,640,800]` + static geometry `[1,8,80,100]`
  → feature `[1,32,80,100]` + confidence logits `[1,4,80,100]`; invoke for
  each camera with its corresponding geometry table.
- `geometry_lut.npz`: OpenCV projection grids, reliability priors, image cues,
  and BEV position cues. The PyTorch transport is the numerical reference for
  a C7x LUT gather/bilinear weighted accumulator. Pool across camera/height
  observations; append four clipped per-height weight sums, normalized weighted
  mean height, and the three position cues. Output `[1,40,384,384]`.
- `bev_detector.onnx`: pooled BEV → heatmap, eight regression channels, quality.
- `metadata.json`: shapes, normalization, class/box order, geometry convention,
  calibration hash, graph operators and decoder score rule.

Pool numerator and denominator in sufficient precision. Invalid observations
have zero prior and out-of-bounds sample coordinates; clamp denominator to
`1e-4`. The transport output is 5,898,240 values: **5.625 MiB INT8**, 11.25 MiB
FP16, or 22.5 MiB FP32. That is approximately the old 147×200×200 feature
handoff despite the larger grid. These figures exclude temporary buffers,
LUTs, weights and all other live tensors; they are not peak-memory claims.
The ONNX profile inventories actual convolution MACs and fixed LUT memory.

The learned graphs use ordinary/3×3 depthwise convolutions, residual adds,
ReLU6, sigmoid gates, concatenation, slices, and nearest resizing. BatchNorm
is folded on export. Geometry sampling/division, score decoding and rotated
NMS stay on C7x/Arm. TI operator constraints depend on the installed SDK:
[TI supported operators](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/master/docs/operators.md).

Compile both graphs with the **actual TDA4VH/J784S4 TIDL SDK**, inspect the
offload report, calibrate INT8 with representative four-bag images plus the
real BEV tensor distribution, and measure device latency and memory. If
head/regression INT8 accuracy drops, evaluate the SDK's mixed-precision
options. No TDA4VH FPS or accuracy parity is claimed by this source change.
